//// CAPITULO 00 - PROPOSITO DEL DOCUMENTO
**** Alcance
- Documento operativo para describir en detalle cada pagina y flujo actual de Listopic.
- Basado en los HTML de public/, los modulos JS page-*.js y estilos en public/style.css.
- Pretende servir como prompt base para una version mejorada sin perder funcionalidades.

**** Notas de estilo del documento
- Se usa ASCII (sin tildes) para evitar caracteres especiales.
- Cada capitulo se marca con "////" y cada subapartado con "****".

//// CAPITULO 01 - MODELO DE DATOS Y CONCEPTOS
**** Entidades principales
- Lista: id, name, categoryId, isPublic, criteriaDefinition, availableTags, reviewCount, followersCount, commentsCount, images.
- Resena: userId, listId, placeId, itemName, scores (por criterio), overallRating, userTags, photoUrl, timestamps.
- Grupo (item agrupado): agrupacion por listId + placeId + itemName; incluye avgGeneralScore, itemCount, place info.
- Lugar: name, location (lat/lng), averageRating, reviewsCount, mainImageUrl, google data, accessibility, serviceOptions.
- Usuario: username, displayName, name, photoUrl, bio, location, defaultDistanceKm, counts de listas y seguidores.
- Archivo: coleccion users/{uid}/archives con subcoleccion items.
- Chat: conversaciones y mensajes en colecciones (via services), con participants y unreadCounts.

**** Identificadores y normalizaciones
- El itemName se normaliza en algunos flujos (lowercase) para agrupar.
- Las categorias tienen alias (id, name, displayName) y normalizacion de tokens (sin acentos).
- Links internos usan listId, placeId, itemName como parametros.

//// CAPITULO 10 - public/index.html (Home / Descubrir)
**** Objetivo
- Discovery de listas, grupos, usuarios, lugares y resenas.
- Feed de novedades de usuarios seguidos.

**** Entradas y parametros URL
- gmap=1, glat, glng, gzoom: abre panel de mapa global y restaura vista.

**** Secciones UI
- Hero con titulo y subtitulo dinamico.
- Tabs: Explorar y Novedades.
- Filtros Explore: chips de categoria y selector de distancia.
- Carruseles (rails): listas top, grupos top, usuarios activos, lugares top, resenas populares, nuevas listas.
- Mapa global en acordeon con boton para centrar ubicacion.
- Footer corporativo humoristico.

**** Interacciones y eventos
- Tabs: cambia panel activo y recalcula overflow de carruseles.
- Chips de categoria: multi-select; chip "Todo" limpia seleccion.
- Mood chips (si existen en DOM): wow/hmm/all alteran filtros por score.
- Selector de distancia: actualiza filtro y solicita geolocalizacion.
- Rail nav: botones izquierda/derecha hacen scroll horizontal por ancho del rail.

**** Datos y queries (Firestore/Functions)
- categories: se cargan ids, se cachean en ui.getCategoryCache.
- lists (isPublic, orderBy reviewCount/createdAt).
- places (orderBy averageRating) + reviewsCount.
- collectionGroup reviews para top grupos, hot reviews y top users.
- getPlacesForList (cloud function) para hero de lista si no tiene imagen.

**** Algoritmos y reglas
- Filtro mood:
  - wow: score >= 4.
  - hmm: 0 < score <= 3.2.
  - all: sin filtro.
- Filtro por categoria: compara categoryId de lista o categoryId de resena.
- Filtro distancia:
  - buildDistanceChecker usa lat/lng del usuario y L.latLng.distanceTo.
  - Si no hay geolocalizacion, se desactiva el filtro.
- Top grupos:
  - Enriquecimiento de resenas.
  - Agrupa por listId + placeId + itemName (normalizado).
  - Calcula avgScore y count.
  - Dedup por place+item para evitar repetidos.
- Top usuarios:
  - Agrupa por userId y calcula count + avgScore.
  - Complementa con doc user (avatar, username, followers).

**** Mapa global
- Leaflet con tiles claros/oscuros segun theme.
- Marcadores con icono custom por score.
- Popup con imagen, score, resenas y CTA a place-detail.
- Circulo de distancia (si filtro activo).
- setGlobalMapParamsInUrl persiste estado en URL.

**** Feed Novedades
- Requiere usuario autenticado.
- Lee following de users/{uid}/following.
- Query collectionGroup reviews con where in (chunks de 10).
- Filtra resenas de listas privadas.
- Lazy load por batches con uiUtils.setupLazyReviewList.

**** Persistencia
- defaultDistanceKm en localStorage y users/{uid}.
- Estado del mapa en URL (gmap params).

**** Estados y errores
- Placeholders en rails y feed.
- Mensajes cuando no hay seguidos o no hay resenas.
- Warning si geolocalizacion no disponible.

**** Salidas
- Links a list-view, grouped-detail-view, place-detail, profile, search.

//// CAPITULO 11 - public/search.html (Buscar)
**** Objetivo
- Busqueda global con filtros avanzados y atajos semanticos.

**** Entradas y parametros URL
- q= o tag=: precarga query.
- type=: fuerza tipo (all, lists, places, users, items).

**** UI
- Hero con titulo.
- Input principal + boton buscar.
- Botones de tipo de entidad.
- Panel de filtros lateral (colapsable en mobile).
- Barra de filtros activos con chips removibles.

**** Interacciones clave
- Input con debounce (300ms); Enter dispara busqueda.
- Chips de atajo rellenan el input y disparan busqueda.
- Boton filtros abre panel en mobile (backdrop + close).
- Escape cierra panel.

**** Smart tokens y parsing
- @usuario: sugiere type=users y busca sin @.
- #tag: sugiere type=items y busca sin #.
- key:value soporta: tipo/type, categoria, ciudad, provincia, precio, servicios, accesibilidad, rating, seguidores, resenas, badges, residencia, userType.
- Si token coincide con categoria conocida, se convierte en filtro category.
- Normaliza tokens (lowercase, sin acentos).

**** Filtros por entidad
- lists: categoryId (facet), minReviews, minFollowers.
- places: city, province, serviceOptions, accessibility, priceLevel, types, minRating.
- items: listCategoryId, listId (selector), listAvailableTags (baseTags), placeCity, placeProvince, minRating.
- users: userType, residence, badges, minFollowers.

**** Datos y queries
- Algolia indexes: lists, places, users, grouped_items.
- Facets se precargan por query y se cachean por type.
- categories (Firestore) para alias de categorias y fixed-tags.
- lists por categoria (Firestore) para selector de listas de items.

**** Reglas y detalles
- En type=all se ejecuta multipleQueries con 5 hits por index.
- En type especifico, hitsPerPage 20; facets segun definiciones.
- Para lists con filtro de categoria, se filtra client-side por alias.
- En items, baseTags solo aparece si hay categorias seleccionadas.
- listSelector solo aparece si hay categorias y se han cargado listas.

**** Active filters bar
- Renderiza chips con icono y label.
- Click en chip elimina filtro y dispara busqueda.
- Boton Limpiar resetea filtros del tipo actual.

**** Estados
- Placeholder inicial si no hay query.
- Loading spinner durante busqueda.
- Empty state si no hay resultados.
- Error placeholder en fallo de Algolia.

**** Salidas
- Cards a list-view, profile, place-detail, grouped-detail.

//// CAPITULO 12 - public/list-form.html (Crear/Editar lista)
**** Objetivo
- Crear listas con criterios y tags; editar listas existentes.

**** Entradas URL
- editListId= activa modo edicion.

**** UI
- Form con nombre, categoria, toggle publico.
- Imagen con drag/drop, file, URL, preview, borrar.
- Criterios dinamicos con labels y ponderable.
- Modal de opciones avanzadas para min/max/step/type.
- Tags fijas por categoria + tags custom.

**** Carga de datos
- categories desde Firestore para poblar selector y fixed-tags.
- list doc si editListId.

**** Criterios (detalle)
- createCriterionItem crea inputs y hidden fields:
  - criteria_label_*, criteria_labelMin_*, criteria_labelMax_*, criteria_isPonderable_*
  - hidden: criteria_min_*, criteria_max_*, criteria_step_*, criteria_type_*
- Boton Opciones abre modal y escribe hidden fields.
- Remove elimina el criterio.
- Se agrega un criterio vacio adicional por defecto.

**** Tags
- fixed-tags: checkboxes generados desde categoria.
- custom tags: input dinamico con add/remove.
- Al guardar: combina fixed + custom y deduplica.

**** Imagen
- Drop area detecta imagenes; valida mime.
- compressImage reduce peso y crea preview.
- URL input limpia file seleccionado.
- listImageTouched indica si el usuario cambio la imagen.

**** Submit
- Requiere auth.
- Payload incluye name, categoryId, isPublic, criteriaDefinition, availableTags.
- Create: createListWithValidation; luego upload a Storage si hay file.
- Update: updateListWithValidation; mantiene counters existentes.
- Redirect a list-view.html?listId=.

**** Estados
- Notificaciones de exito/error.
- Placeholder en criterios si categoria no define ninguno.
