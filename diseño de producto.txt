//// CAPITULO 11 - public/search.html (Buscar)
**** Objetivo
- Busqueda global con filtros avanzados y atajos semanticos.

**** Entradas y parametros URL
- q= o tag=: precarga query.
- type=: fuerza tipo (all, lists, places, users, items).

**** UI
- Hero con titulo.
- Input principal + boton buscar.
- Botones de tipo de entidad.
- Panel de filtros lateral (colapsable en mobile).
- Barra de filtros activos con chips removibles.

**** Interacciones clave
- Input con debounce (300ms); Enter dispara busqueda.
- Chips de atajo rellenan el input y disparan busqueda.
- Boton filtros abre panel en mobile (backdrop + close).
- Escape cierra panel.

**** Smart tokens y parsing
- @usuario: sugiere type=users y busca sin @.
- #tag: sugiere type=items y busca sin #.
- key:value soporta: tipo/type, categoria, ciudad, provincia, precio, servicios, accesibilidad, rating, seguidores, resenas, badges, residencia, userType.
- Si token coincide con categoria conocida, se convierte en filtro category.
- Normaliza tokens (lowercase, sin acentos).

**** Filtros por entidad
- lists: categoryId (facet), minReviews, minFollowers.
- places: city, province, serviceOptions, accessibility, priceLevel, types, minRating.
- items: listCategoryId, listId (selector), listAvailableTags (baseTags), placeCity, placeProvince, minRating.
- users: userType, residence, badges, minFollowers.

**** Datos y queries
- Algolia indexes: lists, places, users, grouped_items.
- Facets se precargan por query y se cachean por type.
- categories (Firestore) para alias de categorias y fixed-tags.
- lists por categoria (Firestore) para selector de listas de items.

**** Reglas y detalles
- En type=all se ejecuta multipleQueries con 5 hits por index.
- En type especifico, hitsPerPage 20; facets segun definiciones.
- Para lists con filtro de categoria, se filtra client-side por alias.
- En items, baseTags solo aparece si hay categorias seleccionadas.
- listSelector solo aparece si hay categorias y se han cargado listas.

**** Active filters bar
- Renderiza chips con icono y label.
- Click en chip elimina filtro y dispara busqueda.
- Boton Limpiar resetea filtros del tipo actual.

**** Estados
- Placeholder inicial si no hay query.
- Loading spinner durante busqueda.
- Empty state si no hay resultados.
- Error placeholder en fallo de Algolia.

**** Salidas
- Cards a list-view, profile, place-detail, grouped-detail.

//// CAPITULO 26 - PROMPT PARA IA (TOMA DE DATOS DE LUGARES Y BUSQUEDA)
**** Objetivo
- Prompt listo para copiar para que otra IA implemente la toma de datos de lugares y la busqueda global igual que la version actual.

**** Prompt sugerido (copiar tal cual)
PROMPT PARA IA:
Eres un ingeniero de software. Debes reproducir EXACTAMENTE la toma de datos de lugares y la busqueda global de Listopic. Respeta nombres de modulos, funciones, endpoints, campos y elementos DOM. No renombres ni simplifiques. Sigue estas instrucciones detalladas:

A) Estructura y dependencias
- Frontend en namespace global ListopicApp.
- Modulos clave: public/js/places-service.js, public/js/page-review-form.js, public/js/uiUtils.js, public/js/page-search.js.
- Backend en functions/modules/core.js con endpoints HTTP y funciones callable.
- Config: ListopicApp.config.FUNCTION_URLS (getPlaceDetails, getPlaceDetailsFromGoogle, placesTextSearch, placesNearbyRestaurants, refreshPlaceMainImage) y ListopicApp.config.ALGOLIA_APP_ID / ListopicApp.config.ALGOLIA_SEARCH_KEY.
- Colecciones Firestore: places, lists, categories, collectionGroup reviews.

B) Toma de datos de lugares - UI de review-form
- Inputs y elementos exactos: #restaurant-name-search-input, #search-by-name-btn, #find-nearby-btn, #restaurant-suggestions.
- Al escribir: limpia seleccion previa (dataset placeSelected) y clases place-found / place-status-*; si input vacio, ocultar sugerencias.
- Enter en input dispara click en buscar.
- Focus sin lugar seleccionado muestra status info con setPlaceSelectionStatus.
- Boton buscar llama ListopicApp.placesService.searchRestaurantsByName(query).
- Boton cercanos llama ListopicApp.placesService.fetchNearbyRestaurantsWithContext().
- Caja de sugerencias: lista UL con items que muestran place.name + (vicinity o formatted_address). Cada item tiene icono plus.
- Click en sugerencia: mostrar loading, llamar getPlaceDetailsFromGoogle via placesService, y usar uiUtils.updateReviewFormWithPlace(detailedPlace). En error mostrar mensaje y status error. Cerrar sugerencias tras 2s.
- updateReviewFormWithPlace rellena inputs: #establishment-name, #location-display-name, #location-address-manual, #location-region-manual, #location-google-maps-url-manual, #location-latitude, #location-longitude, #location-googlePlaceId, #location-city-g, #location-postalCode-g, #location-country-g. Marca dataset placeSelected=true y clases de exito.
- Si la URL trae placeId, precarga desde Firestore places/{placeId} y llama updateReviewFormWithPlace.

C) places-service (frontend)
- Implementa callPlaceFunction(functionName, params):
  - Resuelve URL desde ListopicApp.config.FUNCTION_URLS. Si functionName == "getPlaceDetailsFromGoogle" y no hay URL, usa FUNCTION_URLS["getPlaceDetails"] como fallback.
  - Requiere usuario autenticado y adjunta Authorization: Bearer {idToken}.
  - Agrega userId al query string si no viene en params.
  - Maneja errores HTTP con mensaje JSON o status.
- fetchNearbyRestaurantsWithContext():
  - Obtiene geolocalizacion (timeout 10s). Guarda en ListopicApp.state.userLatitude/Longitude.
  - Usa listId actual y categoryId de la lista. Si no esta en state, consulta Firestore lists/{listId} para categoryId y categoryGooglePlaceTypes o categoryGooglePlaceType.
  - Llama endpoint "placesNearbyRestaurants" con latitude, longitude, categoryId y categoryTypes (CSV) si existen.
- searchRestaurantsByName(query):
  - Valida query. Muestra status loading con highlight.
  - Intenta geolocalizacion rapida (timeout 5s) si no hay coords en state.
  - Incluye latitude/longitude si existen, categoryId y categoryTypes si estan en state.
  - Llama endpoint "placesTextSearch".
- refreshMainImage(placeId, options):
  - Llama FUNCTION_URLS.refreshPlaceMainImage con query params force/maxWidth.

D) placesNearbyRestaurants (backend HTTP)
- Requiere auth por request (Bearer token).
- Parametros requeridos: latitude, longitude, categoryId. categoryTypes opcional.
- Resuelve categoryTypes con resolveCategoryPlaceTypes(categoryId, rawCategoryTypes) y allowedTypesSet con buildAllowedTypesSet.
- Busca primero en datos locales: fetchLocalPlacesByTypes(categoryTypes, { userLat, userLon, limit: MAX_PLACES_SUGGESTIONS, maxDistanceKm: MAX_LOCAL_NEARBY_DISTANCE_KM }).
- Si hay suficientes resultados locales (>= MIN_LOCAL_RESULTS_THRESHOLD), devuelve solo locales.
- Si no hay API key, devuelve locales si hay, si no error 500.
- Si necesita Google: usa Nearby Search con rankby=distance y type=primer categoryType o point_of_interest.
- Filtra resultados Google por allowedTypesSet, anota distancia (annotateGoogleResult), y mezcla con locales (mergePlaceResults) con limite MAX_PLACES_SUGGESTIONS.

E) placesTextSearch (backend HTTP)
- Requiere auth. Parametro query obligatorio.
- Opcional latitude/longitude y categoryId/categoryTypes.
- Busca locales primero: searchListopicPlacesByName(trimmedQuery, { userLat, userLon, limit: MAX_PLACES_SUGGESTIONS, categoryTypes }).
- Si hay suficientes locales, devuelve locales.
- Si no hay API key, devuelve locales si hay, si no error 500.
- Si necesita Google: usa Text Search con query, language=es, type=primer categoryType o establishment, y si hay coords agrega location + radius=40000.
- Filtra, anota, mezcla con locales y limita.

F) getPlaceDetailsFromGoogle (backend HTTP)
- Requiere auth. Parametro placeid obligatorio.
- Llama Google Place Details con fields: name, place_id, formatted_address, geometry, url, photos, price_level, website, international_phone_number, address_components, rating, user_ratings_total, types.
- Extrae city (locality), region (administrative_area_level_1), country, postalCode. Deriva province por los 2 primeros digitos del postalCode usando provinceMap.
- Obtiene accesibilidad con fetchPlaceAccessibilityOptions(place_id, apiKey) y combina con resolveAccessibilityPayload.
- Resuelve mainImageUrl desde la primera photo_reference (800px) si existe, si no conserva el valor previo.
- Guarda en Firestore places/{place_id} con merge:true y campos:
  - name, name_normalized, googlePlaceId, address, address_normalized,
  - coordinates {latitude, longitude} y location {latitude, longitude},
  - city, region, province, country, postalCode,
  - googleMapsUrl, website, phone,
  - priceLevel, googleRating, googleUserRatingsTotal, types,
  - mainImageUrl, mainImagePhotoReference,
  - accessibility, serviceOptions,
  - updatedAt, lastGoogleSync.
- Si es nuevo: createdByUserId, createdAt, followersCount=0, reviewsCount=0, averageRating=null.
- Responde el documento guardado con id.

G) Mantenimiento de imagenes
- uiUtils.refreshPlacePhotoIfNeeded(place) llama placesService.refreshMainImage si mainImageUrl es legacy de Google; cachea promesas por placeId en ListopicApp.state.pendingPlacePhotoRefreshes.

H) Busqueda global (frontend Algolia)
- Pagina search usa page-search.js con estado interno (currentSearchQuery, currentEntityType, filters, facetCache, etc).
- Input #main-search-input con debounce 300ms. Enter ejecuta busqueda. Boton #execute-search-btn ejecuta busqueda.
- Botones de tipo .entity-type-btn (data-type). Seleccionar actualiza filtros y resultados. Tipos: all, lists, places, users, items.
- Panel filtros: #search-filters-panel, #filters-panel-content, #filters-toggle-btn, #filters-backdrop, #close-filters-btn. Barra de filtros activos: #active-filters-bar y #active-filters-chips. Botones limpiar: #clear-filters-btn y #active-filters-clear.
- Placeholder si query vacio y sin filtros en type=all. Spinner durante busqueda. Error placeholder si falla Algolia.

I) Indices y parametros Algolia
- INDEX_NAME_BY_ENTITY: lists, places, users, grouped_items.
