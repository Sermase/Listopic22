//// CAPITULO 00 - PROPOSITO DEL DOCUMENTO
**** Alcance
- Documento operativo con la estructura de datos actual (Firestore + Algolia) y sus relaciones.
- Sirve para alinear la nueva app con los datos existentes sin romper compatibilidad.

**** Notas de estilo
- Se usa ASCII (sin tildes) para evitar caracteres especiales.
- Cada capitulo se marca con "////" y cada subapartado con "****".

//// CAPITULO 01 - CONVENCIONES GLOBALES
**** Identificadores base
- userId: UID de Firebase Auth. Se usa como docId en users/{userId}.
- listId: docId en lists/{listId}.
- placeId: docId en places/{placeId}. Normalmente es Google Place ID.
- reviewId: docId en lists/{listId}/reviews/{reviewId} o reviews/{reviewId} (legacy/new app).
- chatId: docId en chats/{chatId}.
- archiveId: docId en users/{userId}/archives/{archiveId}.
- entityKey: clave sintetica para archives (ej: "place:PLACE_ID" o "group:LIST_ID:PLACE_ID:ITEM").

**** Timestamps
- createdAt, updatedAt, lastGoogleSync, criteriaAveragesUpdatedAt usan serverTimestamp.
- readAt, followedAt, lastInteractionAt tambien usan serverTimestamp.

**** Relaciones claves
- lists/{listId}/reviews usa listId + userId + placeId.
- collectionGroup reviews se usa para feeds, grupos y agregados.
- places/{placeId} se enlaza por placeId desde reviews, grouped items y archive items.
- users/{userId} se enlaza por userId desde listas, reviews, followers, chats, notifications.

**** Campos derivados (contadores)
- reviewCount en lists, places, users.
- followersCount en lists, places, users.
- followingCount en users (mezcla listas, lugares y usuarios).
- commentsCount en lists y reviews.
- criteriaAverages en lists (derivado de reviews).
- averageRating en places (derivado de reviews).

//// CAPITULO 03 - users/{userId}
**** Campos base (perfil)
- username: string (alias principal).
- displayName: string (nombre publico).
- name: string (nombre real, opcional).
- surnames: string (apellidos, opcional).
- email / emailLowerCase: string.
- photoUrl: string (URL imagen perfil).
- bio: string.
- location: string (legacy) / residence: string (filtro).
- dateOfBirth: timestamp|null.
- userType: string o array de strings (ej: "basico", "jefe").
- badges: string[].
- defaultDistanceKm: number.

**** Contadores
- followersCount: number.
- followingCount: number (usuarios + lugares + listas).
- publicListsCount: number.
- privateListsCount: number.
- reviewsCount: number.
- commentsCount: number.
- likes: number (React app, opcional).

**** Timestamps
- createdAt, updatedAt.

**** Subcolecciones
- following/{targetId}
  - Para usuarios: docId = userId seguido, campos: followedAt.
  - Para lugares: docId = placeId, campos: placeId, followedAt.
  - Nota: se mezcla en la misma subcoleccion.
- followers/{followerId}
  - Campos: followedAt.
- followingLists/{listId}
  - Campos: listId, followedAt.
- notifications/{notificationId}
  - type: "new_follower" | "review_comment" | "review_reaction".
  - actorId, actorDisplayName, actorPhotoUrl.
  - followerId / commentSnippet / reactionType segun tipo.
  - listId, listName, reviewId, itemName, detailUrl, reviewPhotoUrl.
  - createdAt, read (bool), readAt (timestamp opcional).
- archives/{archiveId} (ver Capitulo 11).
- archiveIndex/{entityKey} (ver Capitulo 11).

//// CAPITULO 04 - lists/{listId}
**** Identidad y ownership
- name: string.
- userId: string (owner principal).
- ownerId / ownerName / ownerUsername / authorName: strings (opcionales, usados en Algolia).
- isPublic: bool.

**** Categoria y tags
- categoryId: string.
- categoryName: string (opcional).
- availableTags: string[].
- fixedTags: string[] (opcional).
- tagsDefinition: { fixed: string[], userAvailable: string[] } (legacy/opcional).
- categoryGooglePlaceTypes: string[] (opcional).
- categoryGooglePlaceType: string (opcional).
- categoryGoogleTypes: string[] (legacy/opcional).

**** Criterios
- criteriaDefinition: map criterioKey -> {
    label, ponderable, type, min, max, step, labelMin, labelMax
  }.
- criteriaAverages: map criterioKey -> number (calculado).
- criteriaAveragesUpdatedAt: timestamp.

**** Media y agregados
- reviewCount: number.
- followersCount: number.
- commentsCount: number (foros).
- averageRating: number|null (promedio general de reviews, opcional).

**** Imagenes
- mainImageUrl: string.
- coverImageUrl: string (legacy).
- imageUrl / previewImage: string (legacy/opcional).

**** Metadatos
- description, summary: string (opcionales, Algolia).
- createdAt, updatedAt.
- parentListId: string (React app, sublistas).
- likes: number (React app, opcional).

**** Subcolecciones
- reviews/{reviewId} (ver Capitulo 05).
- followers/{userId}
  - Campos: userId, followedAt.

//// CAPITULO 18 - AGREGADOS Y PROCESOS AUTOMATICOS
**** Resenas -> contadores
- Trigger updateAggregatesOnReviewChange en lists/{listId}/reviews:
  - Incrementa/decrementa reviewCount en lists.
  - Incrementa/decrementa reviewsCount en users y places.
  - Recalcula criteriaAverages en lists.

**** Listas -> contadores de usuario
- Trigger updateUserStatsOnListChange:
  - Ajusta publicListsCount / privateListsCount en users.

**** Places -> agregados
- recalculateAggregatesForPlace:
  - Calcula averageRating y reviewsCount desde collectionGroup reviews.

**** Follow/unfollow
- toggleFollowUser: users/{userId}/following y users/{userId}/followers.
- toggleFollowPlace: places/{placeId}/followers y users/{userId}/following.
- toggleFollowList: lists/{listId}/followers y users/{userId}/followingLists.

//// CAPITULO 19 - COMPATIBILIDAD Y MIGRACION (PUNTOS CLAVE)
**** Reviews
- Legacy web: lists/{listId}/reviews con userTags.
- React: reviews/ con tags y sublistId.
- Para unificar, mapear tags -> userTags y sublistId -> listId (parent).

**** Usuarios
- userType puede ser string o array; normalizar a array en la nueva app.
- displayName puede faltar; fallback a username o email.

**** Listas
- ownerId vs userId: usar userId como fuente de verdad.
- tagsDefinition (fixed/userAvailable) convive con availableTags.
- categoryGooglePlaceTypes puede estar en list o category; preferir category.

**** Following
- users/{userId}/following mezcla usuarios y lugares. Diferenciar por:
  - docId que exista en places o users.
  - presencia de campo placeId.
